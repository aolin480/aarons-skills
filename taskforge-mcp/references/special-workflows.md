# Special workflows

Read this reference only when the matching special case is in scope. Then read
the named detailed reference and every ordinary workflow reference the action
also needs.

| Special case | Required detailed reference |
| --- | --- |
| Author, update, familiarize with, or merge-validate nonblank `gherkinSpec` | [gherkin-acceptance.md](gherkin-acceptance.md) |
| User explicitly activates the epic branch workflow | [epic-workflow.md](epic-workflow.md) |
| Work spans an initiative or the user activates its branch workflow | [initiative-workflow.md](initiative-workflow.md) |
| Check identity or authorization, or open a protected TaskForge page | [auth-browser-and-identity.md](auth-browser-and-identity.md) |
| User opted into repository-owned roles and the host guard selected attended Codex routing | [attended-codex-routing.md](attended-codex-routing.md) |

Special workflows are never inferred from ticket type, a linked initiative,
available tools, credentials, role files, or a running client. They do not
weaken the root approval, evidence, branch, status, or merge-proof rules.
